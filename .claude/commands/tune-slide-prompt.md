# tune-slide-prompt

系統性地改善 AI 簡報生成的 prompt 品質。先定義要改善的問題，再做最小改動，最後比較前後差異。

## 使用方式

```
/project:tune-slide-prompt
```

執行前請先描述問題，例如：
- 「生成的投影片文字太少，感覺空洞」
- 「封面頁沒有正確顯示 Siyulio Slide Studio 字樣」
- 「目錄頁結構不夠清楚」
- 「深色主題的文字跑到白色背景上」

---

## 執行流程

### Phase 1：問題定義

在動 prompt 之前，先回答這三個問題：

1. **What**：具體問題是什麼？（貼出壞的生成結果片段）
2. **Where**：問題出在哪幾張投影片？（封面 / 目錄 / 內容頁 / 結尾）
3. **Root cause**：是 prompt 指示不夠清楚，還是 AI 沒遵守指示？

> 如果是「AI 沒遵守指示」，可能需要更強硬的指令語氣（「必須」「不得」），或把規則移到 prompt 更前面。
> 如果是「指示不夠清楚」，補充具體的 HTML 結構範例。

---

### Phase 2：定位修改點

打開 `app/api/generate/route.ts`，找到 `buildPrompt()` 函式。

Prompt 的結構分為四段：

```
[1] 角色設定 — 你是一個專業的簡報設計師…
[2] 色彩指示 — 背景色 / 強調色 / 主文字 / 副文字
[3] 輸出格式 — JSON schema 定義
[4] 投影片要求 — 8 張、各頁職責、HTML 結構規則
```

確認問題屬於哪一段，只修改那一段。

---

### Phase 3：最小改動原則

**一次只改一件事。** 常見改動類型：

| 改動類型 | 範例 |
|----------|------|
| 強化指示語氣 | 改「請確保」→「必須」、「不得省略」 |
| 補充具體範例 | 在指示後加一段 HTML 範例片段 |
| 調整約束條件 | 改字數限制、張數、標題格式 |
| 色彩指示精確化 | 把「主文字」改成「所有 `<p>` 和 `<h2>` 元素的 color」 |

---

### Phase 4：測試比對

用同一個主題，用新舊 prompt 各生成一次，記錄結果：

**測試主題（固定用這個）：** `「如何在傳統產業導入 AI 工作流」`

| 指標 | 改前 | 改後 |
|------|------|------|
| 封面標題是否完整 | | |
| 目錄是否有 3–5 項 | | |
| 內容頁文字是否充實 | | |
| 色彩是否正確套用 | | |
| 結尾頁是否有謝謝語 | | |

---

### Phase 5：決策

- ✅ 改後明顯更好 → Commit，記錄進 Decisions Log
- ⚠️ 有改善但有副作用 → 繼續微調，不要同時改兩個地方
- ❌ 沒有改善 → Revert，重新 Phase 1 找 root cause

---

### Phase 6：記錄

若確認改善，在 `DESIGN.md` Section 8 新增：

```
| YYYY-MM-DD | Prompt 改動：[一句話描述改了什麼] | [改動原因 + 效果] |
```

Commit message 格式：

```
feat(prompt): [改動內容一句話]

Before: [原本的問題]
After: [改善結果]
```
